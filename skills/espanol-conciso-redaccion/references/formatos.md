# Formatos para comprender y comprobar

## Criterios comunes

Identificar primero la dificultad: vocabulario, relaciones, comparación, evolución, variación de parámetros o secuencia de razonamiento. Elegir una representación que la resuelva. No añadir controles, ilustraciones o movimiento únicamente decorativos.

Mantener una idea central y presentar detalles progresivamente. Usar los mismos términos, símbolos y códigos visuales; no depender solo del color. Dejar visibles las condiciones que cambian la interpretación, las fórmulas y las fuentes necesarias para comprobar afirmaciones.

Distinguir observaciones, ejemplos sintéticos y resultados de modelos. Cuando se pidan varios formatos, reutilizar una representación común para evitar contradicciones entre texto, figura y narración. Favorecer recursos pequeños y específicos; una explicación no necesita por defecto cuentas, almacenamiento ni publicación web.

## Diagramas, gráficos e imágenes

Definir el significado de nodos, flechas, posiciones y colores. Usar diagramas sencillos para relaciones; tablas para correspondencias exactas; gráficos para datos. Usar herramientas de dibujo o trazado exacto para geometría, escalas y fórmulas. Reservar generación de imágenes para escenas, ilustraciones y metáforas visuales.

Limitar texto por elemento y dividir una figura densa en vistas conectadas. Añadir una descripción textual breve. Revisar sentido de flechas, unidades, leyenda, contraste y lectura en pantalla pequeña. Un dibujo atractivo no constituye evidencia de un mecanismo; indicar si es esquemático o no está a escala cuando afecte a la interpretación.

Para el estilo de boceto didáctico, consultar [infografías](../../infografias-didacticas-creacion/SKILL.md). Si falta generación de imágenes, esa skill entrega brief y prompt; no sustituye una imagen por SVG sin que se haya elegido esa alternativa.

## HTML interactivo y animaciones

Conectar cada parámetro manipulable con un resultado que responda a la pregunta. Usar pocos controles con rangos válidos, valores y unidades, y un estado inicial informativo. Mostrar qué condiciones quedan fijas; no atribuir a una variable efectos de otras que cambian a la vez.

Permitir comparar estados cuando sea el objetivo. Evitar escalas automáticas que oculten el efecto. Para secuencias, permitir pausa, pasos o control temporal cuando corresponda. Respetar las relaciones del modelo, no usar reproducción automática con sonido y tener en cuenta preferencias de movimiento reducido.

Distinguir un recurso dentro de la conversación de un archivo HTML completo y de una web publicada. Descubrir las capacidades del anfitrión sin depender de un nombre de herramienta. Para uso sin conexión, integrar recursos y eliminar dependencias remotas. Una publicación requiere un encargo que la incluya.

Probar interacción principal, extremos y un caso conocido del modelo. Revisar errores, recortes, controles sin efecto y fórmulas ilegibles en vistas estrecha y amplia. Permitir teclado y pantalla táctil; no esconder información esencial detrás de hover. Una maqueta con controles inactivos no es una simulación funcional.

## Vídeo explicativo

Preparar una secuencia de escenas con una idea, representación, narración y duración aproximada por escena. Una estructura posible es pregunta, intuición, modelo, ejemplo y límites; omitir partes que no aporten. Sincronizar explicación y elemento visual, dando tiempo para observar fórmulas o cambios.

Usar etiquetas breves en pantalla, subtítulos y transcripción. Si se pide un estilo de divulgación matemática, traducirlo a decisiones como construcción progresiva, colores estables y geometría animada, sin imitar la identidad vocal de un autor.

Comprobar herramientas de animación, renderizado y voz disponibles antes de prometer la entrega. Usar una voz genérica o narración autorizada. Si faltan credenciales o servicios necesarios, avanzar con guion y escenas, pero declarar el vídeo pendiente. No insertar claves en recursos compartidos.

Revisar el archivo final: reproducción, pronunciación de símbolos, sincronización, ritmo y subtítulos. Distinguir un MP4 de un guion o de un proyecto sin renderizar. Consultar solo las herramientas y skills necesarias para el formato solicitado, sin cargar todas por adelantado.

## Ejemplos de selección

| Encargo | Representación útil |
| --- | --- |
| Definir soberanía en dos frases | Texto que conserve las condiciones del marco teórico |
| Comparar corrientes filosóficas | Tabla con criterios comunes, sin convertir posiciones en caricaturas |
| Explorar crecimiento poblacional | HTML con tasas, unidades, hipótesis y resultados calculados |
| Entender una reacción química | Diagrama o animación que conserve especies, proporciones y mecanismo admitido |
| Explicar un intervalo de confianza | Secuencia gráfica que distinga parámetro, muestra y procedimiento |

Son elecciones orientativas. El formato y alcance pedidos prevalecen.
